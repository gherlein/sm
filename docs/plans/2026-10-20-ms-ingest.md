# `ms` — ingest proprietary skills into the store — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a second binary `ms` that reads a proprietary agent's skills folder (Claude Code first), discovers every skill in it, and copies each as a clean, standard `SKILL.md` directory into the canonical store (or a given destination), ready for `sm`.

**Architecture:** `ms` is the mirror of `sm`: `sm` fans the store **out** to agents; `ms` ingests **in**. It recursively discovers `SKILL.md` directories under a source tree, normalizes each to a conforming skill directory named for its frontmatter `name`, and writes it whole into the destination (default: the canonical store) with a crash-safe copy. It shares the frontmatter reader and the crash-safe directory copy with `sm` by extracting both into reusable form.

**Tech Stack:** Go 1.26.2, stdlib `flag`, `gopkg.in/yaml.v3` (frontmatter, already a dep). No new dependencies. New binary `cmd/ms`; new packages `internal/skillmeta`, `internal/ingest`, `internal/mscli`; refactors to `internal/store` and `internal/link`.

**Spec:** Output must conform to [`../../SKILLS-DIRECTORY-SPEC.md`](../../SKILLS-DIRECTORY-SPEC.md) (the store/skill-dir contract `ms` writes into). Behavior requirements are in Global Constraints below.

## Global Constraints

- Module `github.com/gherlein/sm`, Go 1.26.2.
- **Build and test ONLY through the Makefile** — `make build`, `make test`. Never `go build`/`go test`/`go vet` directly (a hook blocks it). When editing the Makefile, use the `gherlein:makefile-builds` skill.
- `ms` CLI: `ms [flags] <source> [dest]`. `<source>` is required (a proprietary skills folder). `dest` is optional and defaults to the canonical store `$XDG_DATA_HOME/skills` (default `~/.local/share/skills`). Flags: `--format` (default `claude-code`, the only implemented format; any other value is a loud error), `--force`, `--dry-run`, `-v`/`--verbose`. Exit codes: `0` success, `1` operational error, `2` usage error.
- **Source scope: recursive.** `ms` searches the entire source tree for skill directories — a directory that directly contains a `SKILL.md`. It does **not** descend into a directory once identified as a skill (a nested `SKILL.md` under a skill's bundled content is not a separate skill). It prunes `.git`, `node_modules`, `vendor`, `dist`, `build`. It does **not** follow symlinks during the walk (avoids cycles and escaping the source).
- **Output is conforming and normalized.** Each written skill directory is named for the source skill's **frontmatter `name`** (not its source directory name), validated against `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$`. A source entry with no `SKILL.md`, missing/unparseable frontmatter, or an invalid/empty `name` is **warned and skipped**, never written. The whole source skill directory is copied faithfully (every bundled file); **no provenance marker is written** — the destination is a neutral store.
- **Collisions are safe.** Two source skills resolving to the same `name` (e.g. a personal skill and a plugin skill): the first discovered wins, later duplicates are warned and skipped. A name already present in the destination is skipped with a warning unless `--force`, which replaces it crash-safely. `ms` never silently overwrites.
- **Crash-safe writes.** A skill is staged beside its destination path and renamed into place, so a partial copy never appears; `--dry-run` writes nothing.
- Idiomatic Go: explicit errors, meaningful names, named constants (no magic numbers), small composable interfaces, comments explain WHY, no emoji. Existing `sm` tests must stay green through the refactors.

## Review Focus

- **Nested `SKILL.md`** (a skill's bundled content contains its own `SKILL.md`) → the inner one is **not** discovered as a second skill; discovery stops descending at the first `SKILL.md`. (Task 3)
- **Cross-source name collision** (two discovered skills share a frontmatter `name`) → first wins, the rest warned and skipped; the run still succeeds. (Task 3)
- **Destination already holds the skill** → skipped with a warning unless `--force`; `--force` replaces without leaving a partial directory; a destination entry that is **not** a conforming skill (a hand-placed file/dir) is never clobbered without `--force`. (Task 4)
- **`dest` inside `source` (or equal)** → `ms` must refuse (it would otherwise re-discover what it just wrote); a clear usage/operational error, not a loop. (Task 5)
- **Source skill whose directory name ≠ frontmatter `name`, or with uppercase/invalid chars in the dir name** → the written skill is named for the (validated) frontmatter `name` and conforms; an invalid frontmatter `name` is skipped, not written as a malformed store entry. (Task 3, exercised in Task 5)

### Task 4: Skill writer (`internal/ingest`)

**Files:**
- Create: `internal/ingest/write.go`, `internal/ingest/write_test.go`

**Interfaces:**
- Consumes: `SourceSkill` (Task 3), `link.CopyDir` (Task 2); plus stdlib `os.Lstat`/`os.RemoveAll`/`os.MkdirAll`.
- Produces:
  - `type WriteResult struct { Written bool; Skipped string }` — `Skipped` is a non-empty reason when the skill was not written.
  - `func WriteSkill(skill SourceSkill, destDir string, force, dryRun bool) (WriteResult, error)` — write `skill` as `destDir/<skill.Name>`. If the target exists: skip (reason) unless `force`, in which case replace it crash-safely. `dryRun` reports what would happen and writes nothing. Creates `destDir` if missing.

- [ ] **Step 1: Write failing tests** in `internal/ingest/write_test.go`:

```
TestWriteSkill_New:            empty dest -> target created with the source's SKILL.md and bundled files; Written true.
TestWriteSkill_SkipsExisting:  target exists, force=false -> not overwritten; Written false, Skipped names the conflict.
TestWriteSkill_ForceReplaces:  target exists with old content, force=true -> replaced with source content; Written true.
TestWriteSkill_DryRun:         dryRun=true on a new target -> nothing written; Written false (would-write reported).
TestWriteSkill_CreatesDestDir: destDir does not exist -> created, skill written under it.
```

- [ ] **Step 2: Run tests to verify they fail** — `make test`; expect `WriteSkill` undefined.
- [ ] **Step 3: Implement `WriteSkill`.** Target `= filepath.Join(destDir, skill.Name)`. Use `os.Lstat` to test existence. On exists && !force → `WriteResult{Skipped: "<target> exists; use --force"}`. On exists && force → remove the existing target (a plain `os.RemoveAll` is acceptable here: the destination is a store `ms` is populating, and `--force` is explicit) then `link.CopyDir(skill.Dir, target)`. On absent → `os.MkdirAll(destDir)` then `link.CopyDir`. `dryRun` short-circuits before any mutation. Validate `skill.Name` as a clean path segment before joining.
- [ ] **Step 4: Run tests** — `make test`; passes.
- [ ] **Step 5: Commit**

```bash

git commit -m "feat(ingest): write a discovered skill into the destination store, with --force and dry-run"
```
